# 修改记录 2026-10-16 · v2.17.21 · 模型名升为行内主角

## 反馈

> 「模型的名字对比度还是低了，不容易发现，应该修改。」（附模型管理页截图：SenseTime商汤 组下 7 行，
> 每行 `模型ID  模型名  OpenAI Compatible  免费  文本  JSON  5h限额  思考映射  智能超时`）

## 诊断：主信息被自己的徽章压过去

先量后改。把模型行里每类文字对卡片底的对比度都算出来：

| 元素 | 暗色 CR | 亮色 CR | 说明 |
|---|---|---|---|
| `--ink` 正文基准 | **13.46** | **17.91** | 一行里主信息应有的水平 |
| `.model-name` 模型名 | 6.47 | 6.40 | 只有正文的三分之一到二分之一 |
| `.model-id` 模型 ID | 4.66 | 5.32 | 勉强过 AA 4.5 |
| `.badge-ok`「免费」徽章 | **10.08** | 3.96 | 暗色下比模型名**高 3.6**，还自带底色与边框 |

**暗色下的倒挂最刺眼**：一行里最该被看到的模型名（6.47）反而不如自己那颗「免费」徽章（10.08）显眼。
徽章有色底 + 描边 + 圆角三重强化，模型名却只有颜色一项在起作用，扫读时视线先落在徽章上。

## 根因：v2.17.15 P2-3 的意图从未真正落地

原注释写的是「22 字符 mono 退到第三级，**模型名当主角**」，但实现把两者**一起降级**了：

```css
.model-row .model-id   { color: var(--ink-tertiary); font-size: 12px;   }  /* 第三级 ✓ */
.model-row .model-name { color: var(--ink-subtle);   font-size: 12.5px; }  /* 第四级 ✗ */
```

ID 退到第三级是对的，但名字被放到了比 ID **更弱**的第四级——注释与实现相反。

## 修法

`.model-name` 回到 `--ink`，13px / 500：

| | 改前 | 改后 |
|---|---|---|
| 颜色 | `--ink-subtle` | **`--ink`** |
| 字号/字重 | 12.5px / 400 | **13px / 500** |
| 暗色 CR | 6.47 | **13.46**（= 正文基准） |
| 亮色 CR | 6.40 | **17.91**（= 正文基准） |

`.model-id` **维持** `--ink-tertiary` 不动——一是这本来就是 P2-3 的正确部分，
二是回归套件 T40v 以精确子串钉死了该行（含 `color: var(--ink-tertiary)`），改动会破锚点。

改后三级阶梯清晰：**供应商名 15px/600 › 模型名 13px/500 › 模型 ID 12px/400(tertiary)**，
模型名不再与装饰性徽章争视觉权重。

## 验证（8660 · Playwright 多视口）

- 双主题实测：`.model-name` CR 与 `--ink` 正文基准**完全一致**（暗 13.46 / 亮 17.91）；
  暗色下已反超徽章（13.46 > 10.08），倒挂消除。
- 1920/1440/768/390 四档 `scrollWidth == clientWidth` 零横滚；13 行模型行高集合
  `[45, 46]`（仅差 1px border-top，桌面整齐）；无任何模型名被截断（`scrollWidth > clientWidth` 计数 0）。
- ≤1199 徽章独立成行的既有布局未受影响（行高 101-131px 正常）。
- `node --check` 过；回归 293/293 全绿。
