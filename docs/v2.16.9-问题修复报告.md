## 1. 问题① 非管理员 Key 的用量历史全空（后端，需重启网关）

**现象**：面板「API 密钥」页点开任意用户 Key 的「用量历史」，图表全 0；只有「管理员（服务器密钥）」伪 Key#0 有数据。**与 Key 是否设限额无关的假象**：设了限额的 Key 其实有数据（表里有行），**未设限额的 Key 和管理员类型 Key 永远没有**。

**根因**：`app/core/keyauth.py` 的 `charge_key_usage()` 第一行 `if is_admin_key(key) or not _has_limit(key): return`——直接早退，函数末尾的小时桶写入 `db.add_hourly_usage(...)` 对这两类 Key 永远不执行。而管理员伪 Key#0 的用量历史走 `get_admin_hourly_usage()`（decision_log `caller='管理员'` 聚合），所以只有它有图。

**修法**：

1. **keyauth.py：`charge_key_usage` 整函数替换**（限额计量语义不变，仅把小时桶写入挪出早退路径）：

```python
async def charge_key_usage(key: dict, amount: int):
    """按用户 Key 的限额语义计量用量，并写入小时桶记录。

    限额计量仅对设了限额的用户 Key 生效（管理员 Key / 未限额忽略）；
    小时桶记录（用量历史数据源）对所有 Key 恒写——否则未限额 Key 的
    用量历史弹窗恒为全 0（v2.16.9 修复）。"""
    key_id = key["id"]
    limited = not is_admin_key(key) and _has_limit(key)
    now = time.time()
    state = await db.get_key_usage(key_id) if limited else None
    if limited and state is None:
        await db.init_key_usage(key_id)
        state = await db.get_key_usage(key_id)

    async with db.bulk():
        if limited:
            if key.get("token_type") == "daily":
                if state.get("last_reset_date") != _today():
                    await db.reset_key_usage(key_id)
                await db.add_key_usage(key_id, amount)
            elif key.get("token_type") == "rolling_5h":
                ws = state.get("window_start")
                if ws is None or (now - ws) >= ROLLING_5H_SECONDS:
                    await db.reset_key_usage(key_id)
                await db.add_key_usage(key_id, amount)
            elif key.get("token_type") == "one_time":
                if not state.get("expired"):
                    await db.add_key_usage(key_id, amount)
                    s = await db.get_key_usage(key_id)
                    if int(key.get("limit_amount", 0)) > 0 and s.get("used_amount", 0) >= int(key.get("limit_amount", 0)):
                        await db.expire_key_usage(key_id)

        # 1h 粒度用量记录（供历史查询；管理员/未限额 Key 也记录）
        await db.add_hourly_usage(key_id, _hour_key(), amount)
```

2. **main.py：四处计费点的判定从 `is_user_key` 放宽为「带 Key 即入账」**。用 `grep -n "charge_key_usage" app/main.py` 找齐调用点（本仓库四处），逐处把包住它的 `if is_user_key:` 改成 `if key:`：

   - chat 流式：`if is_user_key: stream = _wrap_key_stream(stream, key, key.get("billing_mode", "token"))` → `if key:`（`_wrap_key_stream` 的 docstring「流式响应用户 Key 计量」可顺手改为「流式响应 Key 计量（用户 Key / 管理员类型 Key）」）；
   - chat 非流式：`if is_user_key:` + `amount = 1 if key.get("billing_mode") == "request" else response.usage.total_tokens` → `if key:`;
   - `/v1/embeddings`：`if is_user_key:` + `amount = 1 if ... else int(usage.get("total_tokens", 0) or tokens or 0)` → `if key:`;
   - `/v1/rerank`：同 embeddings → `if key:`。

   **三条红线**：
   - **只改「计费/入账」处的判定**。`is_user_key` 守着的三处**配额预检**（`is_pool_allowed` 池授权、`key_usage_available` 限额判满）**保持原样**——管理员类型 Key 必须继续绕过授权与限额。
   - 服务器密钥路径 `key = None`（`verify_key` 返回 `{"kind": "server_admin", "key": None}`），`if key:` 自然跳过，其用量历史仍走伪 Key#0 的 decision_log 口径，**不要**给它造 key 记录。
   - `app/gateway/search_summary.py` 的 `_charge_dedicated` 已经无条件委托 `charge_key_usage`，行为自动跟随；只需把 docstring 里「管理员 Key、未设限额自动忽略——与 charge_key_usage 行为对齐」改为「限额计量对管理员 Key、未设限额自动忽略（小时桶记录恒写）——与 charge_key_usage 行为对齐」。

**验证**：回归「无限额 Key 调用一次 → `GET /admin/keys/{id}/usage` 的 total > 0」+「管理员类型（`type=admin`）Key 同样 total > 0」（本仓库 T38a/T38b，可整段拷贝，见附录 A）。8660 实测见附录 D 第 1 项。

## 2. 问题② 统计四视图首开刷新慢（双面板，刷新即见）

**现象**：切到「按计费量/按供应商/按模型池/按付费量」任一视图，第一次渲染要等明显久于后续 5s 轮询；远程/手机访问尤甚。

**根因**：双面板 `loadStats()` 是**串行两轮网络往返**：先 `await api('/stats')`，回来之后才 `Promise.all([statMeta('providers'), statMeta('pools'), statMeta('models')])` 拉视图元数据。后端各端点都是毫秒级（本仓库实测 /stats 9-26ms、元数据 2-5ms），慢在往返次数：RTT 高的链路下首开耗时 ≈ 2×RTT + 渲染；后续 5s 轮询因元数据有 30s TTL 只发一个请求所以不慢。

**修法**（双面板 `loadStats()` 开头，把「先 await /stats 再拉元数据」改成同拍并行）：

```js
async function loadStats() {
  const seq = ++_statLoadSeq;
  // v2.16.9 首开提速：/stats 与视图元数据并行拉取（原串行——等 /stats 回来才拉元数据，慢链路下首开白等两倍往返）
  const metaNeed = statDim === 'provider' || statDim === 'pool' || statDim === 'paid';
  const dataP = api('/stats');
  const metaP = metaNeed ? Promise.all([statMeta('providers'), statMeta('pools'), statMeta('models')]) : null;
  const data = await dataP;
  if (seq !== _statLoadSeq) return;
  // ……（原有的 !data 失败兜底、grid 获取照旧）……
  let provs = [], poolsCfg = {}, cfgModels = [];
  if (metaP) {
    [provs, poolsCfg, cfgModels] = await metaP;
  if (seq !== _statLoadSeq) return;
  }
```

**定位锚点**：函数内原有的 `const data = await api('/stats');` 及紧随其后的 `if (statDim === 'provider' || statDim === 'pool' || statDim === 'paid') { [provs, poolsCfg, cfgModels] = await Promise.all([statMeta('providers'), statMeta('pools'), statMeta('models')]); if (seq !== _statLoadSeq) return; }` 两段——整体替换为上面的结构。**注意**：目标分支若 loadStats 里有本仓库没有的额外逻辑（如 reasoning_auto 相关行），只动「fetch 编排」这两段，其余原样保留。`statDim === 'billing'` 时 `metaP = null`，行为与原先一致（本来就只发一个请求）。

**验证**：浏览器 DevTools Network 面板：清 `_statMeta` 缓存（或冷启动）后切「按付费量」，`/stats` 与 `/admin/providers|pools|models` 四个请求应**同一时刻发出**（Start Time 相差 ≤几 ms）。

## 3. 问题③ 按模型池视图：嵌套池只显示一次 → 多处出现 + 子池计费卡片（双面板，改动最大）

**现象**：模型池存在嵌套（`model_ids` 里有 `pool:子池`）或同一模型属多个池时，模型在「按模型池」视图整页只出现一次；父池组里完全看不到子池的存在。

**根因**：`loadStats()` 池维度装配逻辑 `const poolOf = {}; ... if (!String(id).startsWith('pool:') && !poolOf[id]) poolOf[id] = pn;`——「取第一个收录该模型的全局池」+ 丢弃 `pool:` 条目；且分组渲染的卡片复用键是 `x.m.id`（`statCardEnsure` 的 `prev[x.m.id]`），同一模型在两组出现会互相抢卡。

**修法**（双面板各三处 + CSS；语义：**模型在其直接所属的每个全局池各出现一次；父池组内的子池不展开模型，以一张子池计费卡片代替**）：

1. **loadStats 的池维度装配分支整段替换**。定位锚点：`if (statDim === 'provider' || statDim === 'pool') { ... poolOf ... }` 与其后的 `items.sort(byUsageDesc); statRender(grid, items);`。替换为（index 版；**hfadmin 版唯一差别**：子池条目多一个 `costBtn: ''` 字段——hfadmin 的 `statCardHTML`/`statUpdateCard` 模板含 `${x.costBtn}`，缺了会渲染出字面量 "undefined"）：

```js
  if (statDim === 'provider') {
    // 供应商组：provider_id → 供应商名；独立模型（直连无供应商）按协议归「独立模型」组。
    const provName = pid => { const p = (provs || []).find(z => z.id === pid); return (p && p.name) || pid || ''; };
    items.forEach(x => {
      const pid = x.m.provider_id || '';
      x._gkey = pid ? 'p:' + pid : 'i:' + (x.m.provider || 'openai');
      x._glabel = pid ? provName(pid) : '独立模型 · ' + (x.m.provider || 'openai');
    });
    items.sort(byUsageDesc);
  } else if (statDim === 'pool') {
    /* 模型池组（嵌套池改版）：模型在其直接所属的每个全局池各出现一次（多处归属不再去重，
       卡片键 @池名 防同卡被多组争抢）；父池组内的子池不展开模型，以一张子池计费卡片代替
       （聚合整棵子树去重后的今日 token，卡片样式 stat-subcard 区别于模型卡）。专属池不参与。 */
    const poolDirs = {};
    Object.keys(poolsCfg || {}).forEach(pn => {
      if (poolsCfg[pn].owner_key_id) return;
      const d = { models: [], subs: [] };
      (poolsCfg[pn].model_ids || []).forEach(id => {
        const s = String(id);
        if (s.startsWith('pool:')) d.subs.push(s.slice(5)); else d.models.push(s);
      });
      poolDirs[pn] = d;
    });
    const statById = {};
    items.forEach(x => { statById[x.m.id] = x; });
    const treeCache = {};
    const treeModels = pn => {   // 子树全模型（去重防环）：子池卡片的聚合口径
      if (treeCache[pn]) return treeCache[pn];
      const seen = new Set(), out = [], visit = (p, path) => {
        if (!poolDirs[p] || path.has(p)) return;
        path.add(p);
        poolDirs[p].models.forEach(id => { if (!seen.has(id)) { seen.add(id); out.push(id); } });
        poolDirs[p].subs.forEach(sp => visit(sp, path));
      };
      visit(pn, new Set());
      return treeCache[pn] = out;
    };
    const expanded = [];
    items.forEach(x => {
      const owners = Object.keys(poolDirs).filter(pn => poolDirs[pn].models.includes(x.m.id));
      if (!owners.length) { x._gkey = 'q:__none__'; x._glabel = '未入池'; expanded.push(x); return; }
      owners.forEach(pn => expanded.push({ ...x, _gkey: 'q:' + pn, _glabel: pn, _ckey: x.m.id + '@' + pn }));
    });
    expanded.sort(byUsageDesc);
    // 子池计费卡片：挂父池组、排直接模型之后（此时追加不再参与排序）
    Object.keys(poolDirs).forEach(pn => poolDirs[pn].subs.forEach(sp => {
      const ids = treeModels(sp);
      const agg = ids.reduce((s2, id) => { const y = statById[id]; return y ? s2 + (y.m.today_tokens || 0) : s2; }, 0);
      expanded.push({
        _sub: true, _ckey: 'pool:' + sp, _gkey: 'q:' + pn, _glabel: pn,
        m: { id: 'pool:' + sp, name: sp, today_tokens: agg },
        used: agg, limit: 0, unit: 'tokens',
        numsTitle: '子池 ' + sp + '：整棵子树去重后 ' + ids.length + ' 个模型的今日 token 合计',
        limitText: '—', pct: 0, cls: 'stat-subcard', pctText: '子池', billing: '子池计费',
        typeBadge: '<span class="badge b-once">子池</span>', freeBadge: '',
        refresh: '含 ' + ids.length + ' 个模型', mark: null, limitNote: '', loadText: ''
      });
    }));
    items.length = 0;
    items.push(...expanded);
  }
  if (statDim !== 'pool') items.sort(byUsageDesc);   // 池维度已在分支内排序（子池卡追加其后，不参与排序）
  statRender(grid, items);
```

   语义要点（目标分支如对口径有异议先读这段）：①**专属池**（`owner_key_id` 非空）照旧不参与分组，其成员自然落「未入池」；②子池卡片聚合**整棵子树**（直接模型 + 递归子子池），子树内去重、`path` 防环；③克隆条目的 `_ckey = 模型id + '@' + 池名` 是卡片复用键，三个渲染函数都要跟着改（见下）；④子池卡在组内排在直接模型之后（追加时排序已完成，天然不参与 `byUsageDesc`）；⑤`items` 在本仓库是 `const` 数组，用 `items.length = 0; items.push(...expanded)` 原地替换——目标分支若声明为 `let` 可直接赋值。

2. **卡片复用键三处跟着 `_ckey` 走**（双面板；锚点均为唯一出现，直接替换）：

   - `statCardEnsure`：`let el = prev[x.m.id];` → `let el = prev[x._ckey || x.m.id];`；

   **不要动** `statRenderFlat`（按计费量平铺）里的 `x.m.id`——克隆条目只存在于池维度，平铺视图收不到。

## 4. 问题④ 按池筛选调用记录显示旧数据（双面板，刷新即见）

**现象**：调用记录页选了具体池后，新调用在「全部池」能看到，切到该池的筛选视图却显示旧数据/缺新记录，观感是"具体池没有全部池更新得快"。

**根因**：后端过滤本身正确（`get_decisions` 的 `pool_name = ?` 精确匹配，调用也确实记在请求的顶层池名下）。真正的毛病是前端 `loadDecisions()` **没有并发序号守卫**：切池筛选（onchange）与 5s 轮询并发时，**旧筛选条件发出的请求晚返回，会把当前视图整个覆盖成旧数据**；慢链路下晚到概率大增。同文件 `loadStats()` 早已用 `_statLoadSeq` 解决过同款问题，`loadDecisions` 漏了。

**修法**（双面板两处）：

1. 定时器声明区（锚点：`let statsTimer = null;` / `let logsTimer = null;` 附近）加一行：

```js
let _logLoadSeq = 0;   // 加载序号：切池筛选与 5s 轮询并发时，旧筛选的晚到响应自行丢弃（防旧数据覆盖当前视图）
```

2. `loadDecisions()` 开头加守卫（锚点：函数首两行取 `poolFilter`/发 url，`await api(url)` 之后立即判）：

```js
async function loadDecisions() {
  const seq = ++_logLoadSeq;
  const poolFilter = document.getElementById('log-pool-filter').value;
  const url = '/admin/decisions?limit=100' + (poolFilter ? '&pool=' + encodeURIComponent(poolFilter) : '');
  const data = await api(url);
  if (seq !== _logLoadSeq) return;   // 旧筛选的晚到响应：直接丢弃，不覆盖当前视图
  const el = document.getElementById('log-list');
```
