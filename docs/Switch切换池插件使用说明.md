# Switch 切换池插件使用说明

> 插件标识：`switch_pool`（插件中心 managed 域插件，可热插拔）
> 深度设计文档（路由规则/错误语义完整版）：[docs/Switch切换路由说明.md](Switch切换路由说明.md)

---

## 这是什么

对开启了「🔀 Switch 切换」的模型池，提供**不走 `/v1`** 的定向调用入口：

```http
POST /{池名}?switch=local|net
```

网关把请求**只路由到该池的本地侧或云端侧**模型。典型场景：dsh 脱敏网关按策略决定本轮必须走本地（脱敏）或云端（更强能力），宁可失败也不允许静默跨侧。

**核心语义红线：绝不静默跨侧**——请求侧模型全部不可用时直接 `503`，不滑向另一侧、不进兜底池、不受"单模型锁定"影响。

---

## 快速开始（三步）

### 第 1 步：插件中心启用插件

管理面板 → 插件中心 → **Switch 切换池** → 启用。启用即注册 `POST /{池名}` 路由，停用即时注销（停用期间这些请求得到 404，重新启用立即恢复，全程无需重启网关）。

> 双重开关：插件启用只是装上"入口"；**每个池还要单独打开自己的 Switch 开关**（第 3 步）才会受理切换请求。

### 第 2 步：用「令牌类型」标注模型侧别

不需要新增任何标注，模型管理里现有的**令牌类型**就是侧别：

| 令牌类型 | 侧别 |
|:---|:---|
| `local`（本地） | **local 侧** |
| 其余任意类型（daily / gift / one_time / rolling_5h / request…） | **net 侧** |

### 第 3 步：池卡片打开「🔀 Switch 切换」

模型池管理 → 目标池卡片右上角 → 打开开关（hfadmin 与 admin 双面板均有，保存即热生效）。

开启时服务端立即校验（按池内成员，**含 `pool:` 子池递归展开**）：

| 校验失败 | 报错（400） |
|:---|:---|
| 没有 local 侧模型 | "开启 Switch 需要池内含本地模型：请先将模型令牌类型设为 local（本地）再加入池" |
| 没有 net 侧模型 | "开启 Switch 需要池内含云端模型：当前全部为本地模型（local），请加入至少一个云端模型" |
| 断裂引用/不存在模型 | 400 带具体名单 |

## 怎么调用

`switch` 参数 query、body 两种传法任选（大小写与首尾空格自动忽略）；`model` 字段可省略（携带也会被改写为池名）；`stream`、`max_tokens`、`temperature` 等照常透传；鉴权与 `/v1` 完全一致（**用户 Key 需对该池有授权**，管理员 Key / 服务器密钥天然放行）。

```bash
# query 传参（推荐）
curl -X POST "http://127.0.0.1:8650/default?switch=local" \
     -H "Authorization: Bearer mg-xxxxxxxx" \
     -H "Content-Type: application/json" \
     -d '{"messages":[{"role":"user","content":"你好"}]}'

# body 传参 + 流式
curl -X POST "http://127.0.0.1:8650/default" \
     -H "Authorization: Bearer mg-xxxxxxxx" \
     -H "Content-Type: application/json" \
     -d '{"switch":"net","stream":true,"messages":[{"role":"user","content":"你好"}]}'
```

返回 `200` 为标准 OpenAI 结构（流式为 SSE）。**响应 `model` 字段 = 实际命中的模型接口名**，调用方可借此核对本次真实走了哪一侧。

## 子池穿透（default 拓扑）

池成员**可以全部用 `pool:` 子池引用**，不必直挂任何模型。典型配置：

```
default（开 🔀）
├── pool:local256   ← 子池，全部令牌类型=local 的本地模型
└── pool:netmodel   ← 子池，全部云端模型
```

- `switch=local` → 穿透进本地子池按其策略选模；`switch=net` → 跳过纯本地子池、穿透进云端子池选模。**效果等同把两个子池的全部模型平铺进 default 后再按侧过滤**。
- 侧别判定对子池内模型同样生效，**子池本身不需要任何 Switch 配置**，只有被调用的外层池需要开开关。
- "绝不跨侧"红线对整棵子树生效：所有子池里该侧模型全部不可用时照样 `503`。
- 调用决策记录干净：只有**整棵池（含全部子池）真没有该侧模型**时才记 `switch_no_match`；该侧存在但暂时不可用不会误报。

## 503 的两种文案（排查方向不同）

| 文案 | 含义 | 处理 |
|:---|:---|:---|
| **Switch 切换无候选：池内没有该侧模型** | 整棵池（含全部子池）根本没有该侧模型 | 配置缺侧，管理员补模型/补子池 |
| **所有候选模型均不可用：用量用尽 / 安全阀触顶 / RPM·TPM 触顶 / 冷却 / 超上下文** | 该侧模型**存在但暂时都不可用** | 稍候重试即可，无需改配置 |

其余错误码速查：

| 状态码 | 场景 |
|:---|:---|
| `404` | 池名不存在，或插件已停用（路由已注销） |
| `403` | Key 无该池权限 / 池未开 Switch 开关 |
| `422` | `switch` 缺失或值不是 local/net |
| `429` | Key 用量达限额（与 /v1 一致） |

## 调用记录查询

每次切换都写入决策记录，`requested` 列固定为 `switch:local` / `switch:net`：

- 面板：用量页 → 调用记录（徽标显示侧别与命中模型）；密钥编辑 → 最近调用记录；
- 接口：`GET /admin/decisions?pool=default&limit=50`（管理密码鉴权）。

## 常见问题

**Q：开关打不开，报 400？**
按第 3 步的校验表补齐缺侧模型；若引用了不存在的子池/模型，先修复断裂引用。

**Q：调用返回 404？**
① 池名拼错（对外只能调池，不能直接指定单模型）；② 插件被停用了——去插件中心重新启用。

**Q：调用返回 403「未开启 Switch 切换」？**
池级开关没开（第 3 步），或插件停用导致路由不存在（那会是 404）。

**Q：子池里的模型要改侧别吗？**
子池模型按其令牌类型自动归侧；把某模型令牌类型改出/改入 `local` 即完成换侧，池配置零改动。

**Q：同一个池还能走 `/v1` 吗？**
能。`/v1` 调用不区分侧别、按池策略自由选模，与 `POST /{池名}` 两条入口互不影响。
