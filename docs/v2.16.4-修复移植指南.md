## 1. #45 Anthropic `/v1/messages` 不支持工具调用（Claude Code 类客户端 400）

**现象**：`/v1/messages` 带 `tools` 直接 HTTP 400；不带 tools 一切正常（含 thinking）。`/v1/chat/completions` 带 tools 一直正常。

**根因**：两层。① `app/main.py` 入口有显式 400 拦截；② `app/core/format_adapter.py` 完全没有工具转换。

**修法**：

1. **main.py 摘除 400 门**（删除以下整段）：

```python

if body.get("tools") or body.get("tool_choice"):
    raise HTTPException(
        status_code=400,
        detail="Anthropic 格式暂不支持工具调用（tool_use 转换未实现），请使用 OpenAI 格式",
    )
```

2. **format_adapter.py 补四段转换**（都在既有函数内扩展，无新函数；若目标仓库该文件改动少，最省事是整文件照搬本仓库 v2.16.4 版）：

   - `anthropic_to_openai()`（本仓库 L100 附近）：
     - 顶层 `tools` 数组 → OpenAI `tools`：`input_schema` → `function.parameters`（过滤空/缺 schema 的脏条目）；
     - `tool_choice` 四型映射：`{"type":"auto"}`→`"auto"`、`{"type":"any"}`→`"required"`、`{"type":"none"}`→`"none"`、`{"type":"tool","name":N}`→`{"type":"function","function":{"name":N}}`；
     - assistant 消息内的 `tool_use` 块 → `tool_calls`（`input` 对象转 `arguments` JSON 字符串）；
     - user 消息内的 `tool_result` 块 → 独立 `role:"tool"` 消息（`tool_use_id` 对齐、`is_error` 映射），块外剩余 text 拆成末尾 user 消息——**保持历史顺序**。
   - `_block_to_openai()`（L66）：补识别 `tool_use` / `tool_result` 两种块类型（原仅 text/thinking 等纯内容块）。
   - `openai_to_anthropic_response()`（L278）：响应 `tool_calls` → 追加 `tool_use` 块（id/name/`arguments` JSON.parse 回 input 对象）；`finish_reason=tool_calls` → `stop_reason=tool_use`。
   - `openai_sse_to_anthropic()`（L340，流式）：`delta.tool_calls` 增量 → `content_block_start(type=tool_use)` + 若干 `input_json_delta`（partial_json 累积）+ `content_block_stop`；用 `tc.index` 跟踪分片归属，上游未给名的块补名 `toolu_auto_N`；事件序为 `message_start → content_block_start → input_json_delta* → content_block_stop → message_delta(stop_reason) → message_stop`。

**验证**：回归 T33（10 断言：非流式 tool_use 块与 stop_reason、**上游 payload 形状断言**、历史往返含保序、流式事件序）。手测建议用 UTF-8 文件 + `curl --data-binary @file`（Git Bash 下 curl -d 直接带中文会 400 Invalid JSON body，是编码坑不是服务端）。

## 3. #47 后台管理界面打开慢

**现象**：面板打开慢，远程访问尤其明显；原清单怀疑 N+1 查询。

**根因（已修正）**：管理接口全是纯内存循环（53 模型/22 池规模实测 2.7–5.1ms），N+1 不成立。真凶：双面板 HTML 约 **271KB**，`Cache-Control: no-cache` 且无压缩、无协商缓存——每次打开全量重下。

**修法**：

1. `app/main.py` 加 GZip 中间件（面板 271KB→77KB 降 72%，API JSON 同受益）：

```python
from fastapi.middleware.gzip import GZipMiddleware
app.add_middleware(GZipMiddleware, minimum_size=2048)
```

2. **双面板路由 ETag/304**（main.py `hfadmin_page` L687-712 与 routes.py `admin_page` L91-112 同构）。要点：函数加 `request: Request` 参数；mtime 缓存结构加 `"etag"` 字段；内容变化时重算 md5 ETag；命中即 304：

```python
_hfadmin_html_cache = {"mtime": None, "html": "", "etag": ""}
...
etag = _hfadmin_html_cache["etag"]
if request.headers.get("if-none-match") == etag:
    return Response(status_code=304, headers={"ETag": etag, "Cache-Control": "no-cache"})
return HTMLResponse(..., headers={"Cache-Control": "no-cache", "ETag": etag})
```

保留 `no-cache` 语义（每次再验证，内容未变才 304 零传输）——面板迭代频繁，**不要**改成 max-age 长缓存。

**验证**：`curl -sI` 首次 200 带 `ETag` + `Content-Encoding: gzip`；带 `If-None-Match` 再请求得 304。

## 7. #52 用量历史曲线越界（低于 0 / 高出峰值）

**根因（已修正）**：双面板曲线本就是 Fritsch–Carlson 单调三次插值（原清单「Bezier 平滑」不成立，bezier 命中均为 CSS 过渡），真凶是**漏了切线限幅步骤**：纯尖刺序列不越界（极值点置零规则罩住），但真实流量的爬坡/平台/回落形态（相邻段斜率同号差异大）会越界（实测低至 -259、高出峰值 131）。

**修法**：双面板曲线插值循环补两行限幅（其余不动，Y 轴下界随限幅自然成立）：

```js
for (let i = 1; i < n - 1; i++) {
  if (mp[i - 1] * mp[i] <= 0) { tg.push(0); continue; }   // 极值点：切线置 0
  const lim = 3 * Math.min(Math.abs(mp[i - 1]), Math.abs(mp[i]));   // 限幅：|tg| ≤ 3·min(相邻斜率)
  const avg = (mp[i - 1] + mp[i]) / 2;
  tg.push(Math.sign(avg) * Math.min(Math.abs(avg), lim));
}
```

**验证**：注入爬坡/回落序列采样，曲线全部落在 [0, max]。

## 10. #55 拖拽排序时自动上下滚动检测范围过小

**根因**：① 浏览器原生拖拽边缘检测区约 40px 且不可调；② 自研实现若把 dragstart 挂 document **冒泡**阶段，会被池内条目自身的 `dragstart` `stopPropagation()`（历史问题 14/17 的遗留）吞掉——从池内条目起拖时自动滚动完全不触发。

**修法**（双面板，加在脚本末尾，IIFE 非拖拽期间零开销）：

```js
(function () {
  let dragging = false;
  document.addEventListener('dragstart', () => { dragging = true; }, true);   // 捕获阶段：池内条目的 dragstart 会 stopPropagation，冒泡到不了 document
  document.addEventListener('dragend', () => { dragging = false; }, true);
  document.addEventListener('dragover', e => {
    if (!dragging) return;
    const zone = innerHeight / 4;   // 上下各 1/4 视口
    let d = 0;
    if (e.clientY < zone) d = -Math.ceil((zone - e.clientY) / 6);
    else if (e.clientY > innerHeight - zone) d = Math.ceil((e.clientY - (innerHeight - zone)) / 6);
    if (d) scrollBy(0, d);
  });
})();
```

**验证**：从池内条目起拖至上下 1/4 视口内，页面按深入程度滚动（实测 8 个合成事件约 112/155px）；视口中部不滚。
