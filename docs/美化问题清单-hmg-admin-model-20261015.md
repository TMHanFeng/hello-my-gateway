> 日期：2026-10-15
> 对象：`http://127.0.0.1:8660/hmg-admin/model`，亮色 + 暗色两套主题
> 定调技能：`frontend-design`（大胆只花在一处 / 结构即信息 / 克制自评）
> 方法沿用《美化工作单-hmg-admin.md》§16 的评审纪律：**产出必须是可复核的数值，不是观感形容词**

## 0. 结论先行

「颜色单一」不是错觉，而且**比想象的更极端**。实拍色相直方图：

| 主题 | 无彩色像素占比 | 有彩色像素占比 | 有彩色像素里的色相分布 |
|---|---|---|---|
| **亮色（白）** | **98.2%** | 1.8% | 靛蓝 1.58% · 绿 0.16% · 红 0.07% · 青 0.03% · 橙/紫/黄绿 **0.00%** |
| **暗色（黑）** | 1.7% | 98.3% | **靛蓝 96.82%** · 青 0.45% · 紫 0.38% · 品红 0.34% · 绿 0.21% · 红 0.07% |

两个主题是**同一个病的两种表现**：

- **亮色 = 98.2% 的灰 + 1 个靛蓝按钮**。它不是"配色保守"，它是**几乎无色**——`--canvas` 是纯 `#ffffff`（HSV 彩度 **0.0%**），11 个中性 token 平均彩度仅 **7.4%**。
- **暗色 = 96.8% 的同一种靛蓝**。`--canvas #161823` 的彩度是 **37.1%**，accent `#5e6ad2` 只有 **55.2%**——**背景的彩度吃掉了内容彩度的绝大部分预算**，所以绿色「免费」badge、红色「删除」在暗色里根本跳不出来。

**根因一句话**：**颜色被花在了"背景"上，而不是花在了"意义"上。** 八相位身份色轮（hue0–hue7，实测横跨 36°–329°）在 token 表里躺着，实际只贡献亮色 0.26% / 暗色 1.2% 的像素——**一个覆盖整个色轮的调色板，在界面上的可见面积等于一张邮票。**

前三轮（§18 舷光、§19 每页身份色）都在给**背景**加色，是在错误的层面上加码。§19 自己也写了"alpha 全局统一 .075–.15"——这个量级落在截图上就是看不见，实测确认：暗色/亮色顶部舷光在实拍图中**肉眼不可辨**。

## 2. P0 — 配色结构性问题（这三条改完，单调感会消失一大半）

### P0-1 暗色中性色阶自带 37% 彩度，把颜色预算吃干了

实测（`hmg.css:14-36`）：

| token | 值 | HSV 彩度 | 色相 |
|---|---|---|---|
| `--canvas` | `#161823` | **37.1%** | 230.8° |
| `--surface-1` | `#1e202b` | 30.2% | 230.8° |
| `--surface-2` | `#252834` | 28.8% | 228.0° |
| `--surface-3` | `#2d3040` | 29.7% | 230.5° |
| `--surface-4` | `#353950` | 33.8% | 231.1° |
| `--accent` | `#5e6ad2` | 55.2% | 231.3° |

11 个中性 token 的色相全部落在 **226.0°–231.1°**（跨度仅 5°），彩度 26.8%–37.1%。**所谓"中性色"其实是同一桶饱和靛蓝稀释出来的。**

后果：accent 的彩度只比画布高 **18 个百分点**，语义色（`--ok-ink #5ec974` 彩度 60%）在深色卡片上（surface-1 彩度 30%）也只高 30 个点。**所有颜色挤在同一个窄带里，谁也压不过谁。**

**改法**：把中性色阶降彩度到 8%–14%，把靛蓝**只留给 accent 与氛围层**。

```css
/* 建议值（暗色：真中性 + 一丝靛，不多不少） */
--canvas:          #16171c;   /* S≈ 8%  （原 #161823 37.1%） */
--surface-1:       #1c1d23;   /* S≈ 8% */
--surface-2:       #23242b;   /* S≈ 8% */
--surface-3:       #2a2b33;   /* S≈ 8% */
--surface-4:       #32333c;   /* S≈ 8% */
--hairline:        #2e2f38;
--hairline-strong: #3f414c;
```

**代价要说清楚**：降彩度会让暗色失去现在那点"石墨带蓝"的品牌味。补偿方式是把品牌感**移到氛围层和 accent 上**（舷光、logo、选中光条），而不是压在每一块表面上。这符合 §18 已定的"唯一大胆笔触"原则——现在的问题是**每一块表面都是笔触**。

### P0-2 亮色是纯白纸，`--canvas` 彩度为 0

实测：`--canvas #ffffff`（S=0.0%）、`--surface-1 #f5f6f6`（S=0.4%）、11 个 token 平均彩度 **7.4%**。

亮色主题的整个中性色阶是一张**灰阶照片**，色相集中在 217°–222° 但彩度几乎为零。结果就是实拍的 98.2% 无彩色。亮色主题唯一有彩度的东西是那一个实心紫按钮。

**改法**：

```css
/* 建议值（亮色：带极淡冷调的纸面，比纯白有"材质"） */
--canvas:    #fafafc;   /* 原 #ffffff */
--surface-1: #f3f4f7;   /* 原 #f5f6f6 */
```

`#fafafc` 与 `#ffffff` 对比度 1.03:1——**几乎不可见**，不会破坏 §16.3 刚修好的阶梯塌陷，但让整页不再是一张纯白纸。配合 P0-1 的降彩度思路，亮色也应该往**冷调**统一，而不是现在的暖灰（`#f5f6f6` 其实是暖的，`#eceef1` 已经是冷的，色阶里两种倾向混着走）。

### P0-3 表面阶梯的"画布→卡片"一步几乎不可见（两主题同病）

实算 WCAG 对比度：

| 配对 | 亮色 | 暗色 | 判定 |
|---|---|---|---|
| `canvas` ↔ `surface-1`（**卡片 vs 页面**） | **1.08:1** | **1.09:1** | 极弱 |
| `hairline` ↔ `surface-1`（**卡片边框**） | **1.31:1** | **1.39:1** | 极弱 |
| `surface-1` ↔ `surface-2`（卡片 vs 选中态/徽章底） | 1.07:1 | 1.10:1 | 极弱 |

§17.2 修的是 `surface-1`↔`surface-2` 的塌陷（1.01:1 → 1.07:1），**但真正决定"卡片浮不浮起来"的是 `canvas`↔`surface-1`，这一步至今是 1.08:1**。加上边框只有 1.31:1、阴影在白底上等于没有——**两条深度线索同时贴近地板**，卡片就是一张贴在纸上的贴纸。

对照 §16.4 自己写下的判据：「卡片宜 ≥ ΔL\* 6」。现在亮色 ΔL\* = **3.19**，暗色 = **3.98**，都没达标。

**改法**：

```css
/* 亮色：canvas↔surface-1 拉到 ΔL*≈6（1.14:1 以上） */
--surface-1: #eff0f4;   /* 原 #f5f6f6 */
/* 暗色 */
--surface-1: #20222c;   /* 原 #1e202b */
```

## 3. P1 — 语义与信息设计（颜色该用在哪）

### P1-1 一行 6–8 个同款灰 pill，三条语义轴共用一种视觉语言

实拍（暗色桌面）单行结构：

```
HuoSan-Ark/Doubao-Seed-2.1-turbo  ep-2026…-p8xvn  [OpenAI Compatible] [免费] [多模态] [JSON] [余额返还制] [思考映射]
```

逐条对照代码，这 6 个 pill 属于**三条完全不同的语义轴**，却共用同一种灰 pill（`.badge { background: var(--surface-2); color: var(--ink-muted) }`）：

| 轴 | 徽章 | 代码位置 | 现状 |
|---|---|---|---|
| **能力** | 多模态 / 文本 / embedding / rerank | `model.html:153` | 多模态=灰、文本=灰、embedding/rerank=**靛蓝** |
| **格式** | JSON / 智能超时 | `model.html:286,289` | 灰 |
| **计费** | 免费 / 付费 / 一次性 / 5h限额 / 每日 / 全天可用 / 余额返还制 | `model.html:143-152` | 免费=**绿**、其余全灰 |
| **特性** | 思考映射 | `model.html:288` | **靛蓝** |

**三个具体缺陷**：

1. **优先级倒挂**——最该用色区分的「多模态」（真实差异点）用灰；最不需要用色的「embedding/rerank」（罕见类型）反而是靛蓝。计费档（用户真正的决策依据）**7 种里 6 种是灰的**。
2. **「思考映射」在几乎每一行都是靛蓝**——当一个颜色出现在 90% 的行上，它就不再传递信息，只是噪音。
3. **「免费」是唯一有语义的彩色**——所以它看起来像异常而不是常规。

**改法**：把颜色**只**留给计费轴，一条轴一个视觉语言。

```
计费档（唯一彩色轴）：
  免费   → 绿 tint + 绿字        （现状已有，保留）
  付费   → 中性 pill             （现状已有）
  5h限额 → 琥珀 tint + 琥珀字     （从灰升为语义色）
  一次性 → 紫 tint + 紫字         （从灰升为语义色）
其余轴一律中性，靠位置与字重分组：
  能力（多模态/文本）→ 移到名称下方第二行，与 ep-id 同组
  格式（JSON）        → 降级为 .chip（更小更弱），或直接并入 title
  特性（思考映射）    → 改为无填充描边式（border-only），去底色
```

净效果：**每行从 6 个彩色块降到 1 个**，页面立刻从"彩色噪音"变成"重点突出"。这也是 Chanel 那条建议——摘掉一个配饰。

### P1-2 危险按钮在两套主题里都是全卡最高对比元素 × 24 张卡

代码事实：`model.html:187` 和 `model.html:295` 两处删除按钮用的是 `btn btn-danger`，而**同一张卡上的「编辑」「添加模型」是 `btn-ghost`**。

`hmg.css:271` 的 `.btn-danger { background: var(--err-tint); color: var(--err-ink) }`：
- 暗色 `--err-tint: rgba(235,87,87,.14)` → 实拍是一个**明显的红色块**
- 亮色 `--err-tint: rgba(235,87,87,.08)` → 实拍是淡粉底 + 红字

**问题不是"红得刺眼"，是权重倒挂**：删除是低频、高危操作，却在每张卡上占据全卡最强的色彩对比；编辑和添加模型（高频、常用）是近乎隐形的 ghost。24 个供应商 = 24 个红块排成一列，形成一条贯穿整页的红色视觉轴。

**而项目自己在 §17.2 就已经给出了正确解**：`hmg.css:277` 定义了 `.btn-ghost.danger-hover:hover`（平时与 ghost 同形，悬停才显险），并写明「**安静危险钮——平时与 ghost 同形，悬停才显险**」。这个类**在 model.html 里一次都没用上**。

**改法**（两行）：

```js
// model.html:187 与 :295
- <button class="btn btn-danger btn-sm" onclick="delProvider(...)">删除</button>
+ <button class="btn btn-ghost btn-sm danger-hover" onclick="delProvider(...)">删除</button>
```

这与 §17.2 已做的池成员 ✕ 处理方式一致，属于**把已有规范贯彻到底**，不是新设计。

### P1-3 八相位身份色轮贡献了 1% 的像素

实测色轮覆盖：hue0 234° / hue1 259° / hue2 212° / hue3 194° / hue4 165° / hue5 140° / hue6 36° / hue7 329° —— **横跨 293°，是个合格的全色轮**。

但实拍里它们的可见面积：亮色 **0.26%**、暗色 **1.2%**。原因是它们只用在**一个 20px 的头像方块**上（`.hmg-av`）。头像太小、形状相同、且首字母相同时还会撞相（`model.html` 里商汤1/2/3/4 四个供应商首字母都是「商」，实拍里四个头像**确实几乎一模一样**——§17.4 记录的鸽笼碰撞，在真实数据上已经稳定复现）。

**改法**：让身份色承担**分组功能**而不只是装饰。

1. **头像放大 20px → 26px**，字重提到 600；
2. **供应商卡加一条 3px 左侧色条**（用该供应商的身份色 `--hue*`）——这样扫视整页时，**颜色分区分组**，而不是 24 个小方块各说各话；
3. 首字母相同时，副标题用身份色（`.model-name` / 供应商 id）做区分，撞相问题自然缓解。

在 1280×720 CSS 视口下，视口截图显示主内容区**整片空白**，而同一时刻 `DOM` 文本查询显示 24 个供应商全部存在、`fullPage` 截图也能正常渲染。重载后先出现「加载中…」再变空白。与工作单 §17.3 记录的「§14 冻结伪影」同族，怀疑与 `hmg.css:641-705` 的 `position: fixed` + `z-index: -1` + `backdrop-filter` 氛围层在部分重绘路径下的合成行为有关。
