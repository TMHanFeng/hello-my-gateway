# 修改记录 2026-10-17 · v2.17.24 · 分组头移除删除钮（防误删）

## 反馈

> 「还有个小问题，我希望在首页分组不要出现删除按钮，要删除只能去分组管理中删除，防止出现误删」

## 改动

分组头的 ✕ 与组名、成员计数挤在同一行，点错一下整组归组就没了；而删除本身是
**低频高损**操作（虽然 `grpDelGroup` 带确认框，但入口不该出现在主操作区）。
统一把删除收敛到「分组」设置弹窗 → 分组管理（`grpMgmtDelete`，同样带确认）。

三面板同步（同一个 `grpWrapHtml` 模板在三个地方各有一份）：

| 文件 | 位置 |
|---|---|
| `static/hmg-admin/assets/hmg.js` | `grpWrapHtml()` 分组头模板 |
| `static/index.html` | 同款模板 |
| `static/hfadmin.html` | 同款模板 |

**`.grp-x` 的 CSS 保留**，两个原因：①它是通用原子类，且在 `index.html` / `hfadmin.html`
里被「📊 用量分组查看」弹窗的关闭钮复用；②回归锚点 T40t 以精确子串钉着
`.grp-x { position: relative; }` 与 `.grp-x::before` 的命中区规则，删 CSS 会破锚点。

重命名（双击组名）保留不动——它有二次输入确认，且不属于"高损"操作。

## 防复发：新增 T42 两向断言

这类"把 A 挪到 B"的改动，最怕的回归是**连功能一起删掉**——所以断言写成双向：

| 闸 | 断言 |
|---|---|
| `T42a` | 三面板分组头模板里都**不得**再出现 `grpDelGroup` 删除钮 |
| `T42b` | 三面板的 `grpMgmtDelete` 与 `grpDelGroup` 函数必须**仍在**——分组管理里的删除入口不能被连坐删掉 |

只做单向断言的话，"分组头没了删除钮 ✅ 但管理里也删不掉了 ❌" 这种回归会被放过去。

### 取证陷阱实录（本轮踩到，且被套件当场判红）

T42a 首版写成 `all('grpDelGroup' not in src ...)`——**与 T42b 自相矛盾**：
`grpDelGroup` 的**函数定义必须保留**（分组管理靠它删），T42b 正是断言它在。
首跑套件直接把 T42a 判红（297/298），T41 三闸全 PASS、T42b PASS，说明是断言写错而非产品回归。

修正：T42a 的断言对象应是**模板里的调用**而非标识符存在性——
`grpDelGroup('${kind}'` 零出现 + `class="grp-x" title="删除分组` 零出现；
函数定义仍由 T42b 守住。三面板实测：调用 0/0/0、删除钮模板 0/0/0、
`function grpDelGroup` 各 1、`grpMgmtDelete` 2/2/3。

**教训**：给"移除某个入口"写守卫时，判据要落在**入口的渲染痕迹**上，不要落在**被移除功能的标识符**上——
后者往往还要给别处复用（本例的分组管理）。
