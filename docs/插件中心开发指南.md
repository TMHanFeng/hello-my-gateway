# 插件中心开发指南（v2.14.0）

> Model Gateway 的选配功能以**插件**形式接入：可热插拔（启用/停用/改配置即时生效，无需重启）、
> 开放可扩展（拖入文件夹即可注册新插件）。内置插件：**🔀 Switch 切换池**、**🪴 Headroom 上下文压缩**。

---

## 一、目录结构

```
app/plugins/
├── base.py                  # PluginManifest / GatewayPlugin 协议 / GenericPlugin / schema 校验
├── manager.py               # plugin_center 单例：扫描/装载/启停/配置持久化/请求管线 hook
├── routes.py                # 插件中心 API（/admin/plugins/*）
└── installed/               # ★ 插件安装目录：一个子目录 = 一个插件
    ├── switch_pool/
    │   ├── manifest.json
    │   └── plugin.py
    └── headroom/
        ├── manifest.json
        └── plugin.py
```

## 二、最小插件（零代码，纯配置）

在 `app/plugins/installed/my_plugin/` 放一个 `manifest.json`：

```json
{
  "id": "my_plugin",
  "name": "我的插件",
  "version": "0.1.0",
  "icon": "🚀",
  "description": "一句话说明",
  "kind": "custom",
  "config_scope": "managed",
  "default_enabled": false,
  "config_schema": [
    {"key": "threshold", "type": "int", "default": 100, "min": 0, "max": 9999,
     "title": "阈值", "desc": "设置页自动渲染与校验"}
  ]
}
```

然后 `POST /admin/plugins/scan`（或面板「🔄 扫描新插件」）——卡片立即出现，
具备：启用/停用开关、按 schema 自动渲染的设置表单、配置持久化。

### manifest 字段

| 字段 | 必填 | 说明 |
|:--|:--|:--|
| `id` | ✅ | 全局唯一，建议与目录同名 |
| `name` / `version` | ✅ | 显示名 / 语义化版本 |
| `description` / `author` / `icon` / `homepage` | | 卡片展示 |
| `kind` | | `builtin`（内置）/ `custom`（自定义，默认） |
| `order` | | 卡片排序权重（小在前） |
| `config_scope` | | `managed`（默认）：配置由插件中心托管在 config.json `"plugins".<id>`；`dedicated`：插件自管配置（如 headroom 用 `"headroom"` 节点，兼容历史） |
| `default_enabled` | | 从未持久化过状态时的兜底启停态 |
| `config_schema` | | managed 域设置表单：`{key, type(int\|float\|bool\|str\|enum), default, min, max, options[{value,label}], title, desc}` |
| `ui_hint` | | 卡片上的设置引导文案 |
| `requirements` | | 插件专属依赖清单文件名（相对插件目录）——插件依赖与插件同目录，不进仓库根 requirements.txt |

## 三、带代码的插件（plugin.py）

目录中再加 `plugin.py`，暴露 **`create_plugin(manifest)` 工厂**或模块级 **`PLUGIN`** 实例，
继承 `app.plugins.base.GatewayPlugin`，按需覆写：

```python
class MyPlugin(GatewayPlugin):
    @property
    def router(self):                    # 可选：自带 API，挂载于 /admin/plugin_settings/<id>
        return router

    def is_enabled(self): ...            # dedicated 域必须实现
    def set_enabled(self, flag): ...     # dedicated 域启停落盘
    def get_config(self) / set_config(cfg): ...

    def on_enable(self, app): ...        # 热启用：可 app.add_api_route(...) 注册路由
    def on_disable(self, app): ...       # 热停用：注销路由/释放资源
    def on_startup(self, app): ...       # lifespan 启动钩子
    def on_shutdown(self): ...

    def active_compressor(self):         # 可选：出站压缩 hook
        return self                      # 返回自身即接管 pool 的压缩管线
    async def compress_entry(self, entry, req, pool_name, caller, cache):
        ...                              # 返回（可能改写后的）req；异常请原样返回 req
```

**规则**：
- `plugin.py` 顶层只 import `app.core.*` / `app.plugins.*`，**不要**模块级 import `app.main`
  （会循环导入；需要网关运行时对象时在函数体内 `from app.main import ...`）。
- `on_enable/on_disable` 必须幂等（重复调用不叠加）。
- 任何 hook 异常都不能拖垮网关——参考 headroom 的"故障旁路"写法。

## 四、插件中心 API（均需管理员 Bearer）

| 方法 | 路径 | 说明 |
|:--|:--|:--|
| GET | `/admin/plugins` | 插件列表（元数据+启停态+配置+schema） |
| POST | `/admin/plugins/scan` | 重扫安装目录，发现新插件 |
| GET | `/admin/plugins/{id}` | 插件详情 |
| POST | `/admin/plugins/{id}/enable` | 热启用（即时生效） |
| POST | `/admin/plugins/{id}/disable` | 热停用（即时生效） |
| POST/PUT | `/admin/plugins/{id}/config` | 保存配置（按 schema 校验，热生效） |

插件自带 API 统一挂在 **`/admin/plugin_settings/<id>/*`**（如 headroom 的
`GET/POST /admin/plugin_settings/headroom`、`GET /admin/plugin_settings/headroom/stats?days=7`）。

## 五、两个内置插件

### 🔀 Switch 切换池（`switch_pool`，managed 域，默认启用）
- 功能：对开启 🔀 开关的池支持 `POST /{池名}?switch=local|net` 定向路由（详见《Switch切换路由说明.md》）。
- 插件化：`on_enable` 注册 `POST /{pool_name}` 路由、`on_disable` 即时注销——停用后该请求 404，
  `/v1` 调用完全不受影响。每池自己的开关仍在「模型池」页（双重开关）。

### 🪴 Headroom 上下文压缩（`headroom`，dedicated 域，默认停用）
- 功能：勾选了 Headroom 的模型接单时压缩出站大块工具输出省 token（详见《Headroom选配插件接入计划.md》）。
- 非必装：`headroom-ai` 库未安装时自动旁路（UI 会显示可用性）；配置沿用 config.json `"headroom"` 节点，
  与历史 `/admin/headroom` API 兼容别名共存。
- 需要真实压缩能力时，用插件目录内的 `app/plugins/installed/headroom/requirements.txt` 建独立 venv（或复用源仓库 `.venv-headroom`）并以该解释器启动。
