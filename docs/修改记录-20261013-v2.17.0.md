# v2.17.2（同日追加）：高端感返工——亮度/材质/互动/一致性

## 四项反馈 → 四组修法

| 反馈 | 根因 | 修法 |
| --- | --- | --- |
| 黑太暗伤眼 | Linear `#010102` 是**营销站**画布，高密度工具界面长时间注视必然 halation | 暗色整体升到产品面石墨：canvas `#101116`、surface `#17181f→#2b2e3d`、hairline/ink 同族提亮；亮色 ink 纯黑→`#16171b` |
| 缺鼠标互动 | v2.17.1 的 hover 只有颜色变化，无位移无光影，"死" | 小卡片浮起三件套（-2px + 阴影绽放 + 描边提亮）+ 全卡片**顶部辉光发丝线**（accent 渐变 hairline）；按钮 hover 上浮 + 主按钮辉光投影；侧栏半透明材质内容下滑过 |
| 卡片大小不一致 | stats 网格 `align-items:start`（同行卡片各按内容高） | 去掉 start 改 stretch + 统计卡 flex 纵排 + 进度条 `margin-top:auto` 贴底——同行等高（实测 147/147/147）；内边距统一 16px |

# v2.17.5（2026-10-13）头像对齐修正（v2.17.4 回归）

- **病灶**：`.card-title .hmg-av` 用 `vertical-align:-6px`——实测头像中心比名字文字中心低 7.6px，且 20px 行内片把标题行盒从 22.5px 撑到 28.3px（次行标题被顶开）。
- **修法**：`vertical-align:middle` + 纵向负 margin `margin:-3px 2px -3px 0`（行盒贡献 14px < 22.5 行高，不再膨胀）+ `position:relative; top:-2px` 光学居中。
- **实测**：model/keys 双页头像 vs 文字中心偏差 0.25px（亚像素）；行盒 23.3px；stats `stat-top` 24px 大头像 margin-top -1px 校正（修前对首行 -2.87px）。
- **教训**：行内小片对齐禁止拍脑袋负 px——middle + 负 margin 防膨胀 + relative 微调三件套，量完再定值。

# v2.17.6（2026-10-13）暗色三档提亮 + 科技氛围层

反馈：暗黑太深邃对比太高不舒服、缺动态、无科技特效感。

## 修法

1. **色板第三档**：canvas #101116→#161823、ink #f4f5f9→#e9ebf3，实测对比 17.3:1→**14.8:1**（Linear 暗色同档 14-15:1）；surface/hairline/ink-muted/side-bg 全族上移。三轮沿革：#010102（营销海报黑）→#101116（v2.17.2）→#161823（本轮）。
2. **氛围层**：画布色移到 html、body 透明；`body::before` = 44px 网格 + 顶部双极光 radial（静态 paint 一次）；`body::after` = 极光缓漂 auroraDrift 26s（translate3d/scale/rotate 合成器动画 + 静态 blur 34px）。亮色主题：极光退场、网格换暗线。
3. **恒动细节**：Logo brandFlow 9s、进度条 fillFlow 3.2s 流光（42% 白光条 translateX 循环，零宽条自然无光）、nav 选中 accent 光条、主按钮 hover sheenSweep 扫光一次。

## 关键约束

- 恒动只给氛围与数据流，交互反馈仍是 hover/按压响应（emil：恒动不抢焦点）。
- 全部动画 transform/opacity（合成器线程）；reduced-motion 全局冻结规则自动接管，无需逐个降级。
- T40k 锚点：`--canvas: #161823` + auroraDrift/fillFlow/brandFlow/body::before。

# v2.17.7（2026-10-14）背景丰富化：第二漂移层 + 噪点/暗角/大网格

反馈：「背景是不是太单一了？」——实况成立：v2.17.6 的氛围层全部集中在顶部（两团靛蓝系辉光 + 一团极光），右侧与下 2/3 视口是纯平底色，且所有辉光同一色相。

## 修法

1. **第二漂移层**（`html::before`，fixed 负 z，inset -22% 防漂移露边）：紫 `rgba(178,118,235,.09)` 右下 + 青 `rgba(64,205,255,.07)` 左下——引入两个新色相打破单一靛蓝族；`ambientDrift 38s` 与 auroraDrift 26s 互质不锁步，上/下分踞覆盖全视口。
2. **静态质感层**（`body::before` 4 层→8 层）：胶片噪点（feTurbulence 去饱和 data URI，180px 平铺，.05）抗色带；暗角（transparent 55%→rgba(4,5,9,.38)）加纵深；264px 大网格与 44px 细网格共存（蓝图感）。
3. **亮色同步**：html::before 极淡紫/青晕 + body 右下紫晕；噪点/暗角白底退场。手机 blur 38→26px 省 GPU。

## 本轮真 bug：永不匹配的主题覆盖选择器

- **病灶**：亮色覆盖写成 `:root[data-theme="light"] html::before`——`:root` **就是** html，元素不能是自己的后代，该选择器永不匹配；亮色主题下第二漂移层一直回落暗色紫青色值（.09 白底上偏脏）。
- **修法**：`html[data-theme="light"]::before`（或 `:root[data-theme="light"]::before`）。同文件 `body::before` 的主题覆盖不受影响（body 确实是 :root 后代）。
- **教训**：给 `html::before/::after` 写主题分支时，选择器必须以 `:root[data-theme=…]::before` 收尾——「后代组合器 + html」在这里是静默失效，不报错不告警，只能靠双主题 computed 断言抓出来。

## 验证

- 回归 282→**283** 全绿（新增 T40m：紫青双色/feTurbulence+feColorMatrix/暗角 rgba(4,5,9,.38)/264px 大网格/亮色 `data-theme="light"]::before`/手机 blur(26px) 锚点）。
- DOM 断言（8660）：暗色 body::before 8 层 backgroundSize 全对（auto/180px/auto/auto/44/44/264/264）；ambientDrift@38s blur(38px) fixed z-1 pe:none 与 auroraDrift@26s 同屏；对比 14.8:1 不变（暗角只压暗背景，比率只升）；亮色 html::before tint 在位且无暗色色值；双主题往返正确；卡片级联 #f5f6f6 不受影响；手机 390px blur(26px)。
